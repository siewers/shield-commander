# Shield Commander project guide for agents

## Architecture
- Target framework `net10.0` with nullable and implicit usings enabled.
- Preserve layered boundaries: Core contains models, services, and platform logic (ADB); UI handles presentation with MVVM. The UI layer references Core, never the reverse.
- Keep Core free of UI and application frameworks. Its only package dependency is Zeroconf (network discovery); add others only when they are small abstraction packages, and never UI, MVVM, or DI frameworks.
- UI uses Avalonia with compiled bindings enabled by default. Use `x:DataType` on views.
- UI uses CommunityToolkit.Mvvm: `[ObservableProperty]`, `[RelayCommand]`, and `partial void OnXChanged` for property change reactions.
- LiveCharts2 (`LiveChartsCore.SkiaSharpView.Avalonia`) for time-series charting.
- NuGet package versions are managed centrally in `Directory.Packages.props`. Add `<PackageReference Include="..."/>` without a version in the project, and the version in `Directory.Packages.props`.

## Coding conventions
- Keep one top-level type per file. Nested types are fine within their parent.
- Prefer the latest .NET language/runtime features where appropriate.
- Use trailing commas in multi-line initializers, parameter lists, and collection expressions to simplify diffs.
- Do not use private properties. Use private fields for stored state and private methods for computed values.
- Store the actual dependency you need, not an intermediary object you repeatedly drill into.
- Actively reduce duplication when introducing repetitive code. Consider whether shared abstractions can eliminate repetition structurally rather than just hiding it behind a helper method.
- Avoid instantiating objects inline when passing them to methods; assign to a variable first.
- Make all types `sealed` by default. Only omit `sealed` when a type is explicitly designed for inheritance.
- Line endings are mixed (most C# and project files use CRLF, some use LF) and not enforced by `.editorconfig`. Keep each file's existing line endings when editing.

## General
- Never use emoji in code, documentation, commit messages, or any other project artifacts.
- Do not add AI attribution anywhere: no "generated by AI" comments and no `Co-Authored-By` lines in commit messages.

## Building and testing
- Build with `dotnet build ShieldCommander.slnx`.
- Run tests with `dotnet run --project src/ShieldCommander.Core.Tests`. The tests use TUnit on Microsoft.Testing.Platform.

## Commits and pull requests
- Use simple `git commit -m "message"`; do not use heredocs.
- Make changes through pull requests rather than pushing to `main`, so they appear in the generated release notes.
- Label each pull request so the release notes sort it correctly: `enhancement` (new app features), `bug` (app fixes), or `maintenance` (build, CI, release tooling; not app changes). Dependabot labels its own pull requests `dependencies`.

## Releases
- Versions follow SemVer and come only from the git tag; there is no version file. Builds from source report `0.0.0-dev`.
- Create tags with `scripts/tag-release.sh <major|minor|patch> [alpha|beta|rc]` or the `/tag-release` skill. Pushing a `v*` tag runs the Release workflow, which builds all platforms and publishes the GitHub release.
- Tags with a prerelease suffix (`-beta.N`) are published as prereleases and are not marked as the latest release.

## Device testing
- Test changes on the NVIDIA Shield with `adb connect <IP>`. Try the last known IP first: 10.0.0.150. If it doesn't connect, ask the user for the current IP.
- Disconnect with `adb disconnect <IP>` when done testing.
- On macOS, if `adb connect` fails with "No route to host" while the Shield is reachable, the adb server has lost local network access. Restart it with `adb kill-server` and connect again (see issue #35).
